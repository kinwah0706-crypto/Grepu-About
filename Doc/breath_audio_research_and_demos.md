# 呼吸冥想「声音策略」桌面调研与 Demo 说明

本文档配合目录 `Doc/breath_audio_demos/` 下的可播放文件使用，供你在**不改动代码**的前提下评估：是否投入下一阶段（商用人声 / 内容供应链 / 工程播放管线等）。

---

## 1. 调研目的与边界

- **目的**：把「呼吸引导可以怎么做」从抽象讨论落到**可听的参考**，并记录公开市场上的常见范式与取舍。
- **边界**：未做大规模用户定量研究；竞品信息来自公开页面与行业常识，需后续用访谈与数据验证。
- **与 Grepu 代码的关系（事实摘要）**：当前主线是**计时 + 触觉 + 极短阶段提示音 + 后台静音保活**，界面文案走 `Localizable.json`（多语言）。尚未有「长人声跟练」资产与播放管线。

---

## 2. 桌面调研摘要（可验证方向）

| 方向 | 代表思路 | 对产品的启示 |
|------|-----------|--------------|
| **触觉主导** | 强调闭眼、不依赖声音或屏幕的呼吸节奏（如 HapticMind 类方向） | 与现有触觉能力一致；多语言**零成本**；适合「极简 / 无障碍」叙事。 |
| **多感官叠加** | 人声 + 环境声 + 触觉 + 视觉同轨（常见商业化冥想 App） | 沉浸感强，但**制作与混音成本高**；人设与音色差评风险需预案。 |
| **空间/双耳节奏** | 用空间音频左右交替等锚定注意（如部分 breathwork / bilateral 类产品） | 差异化强；需评估技术、耳机场景、与「放松」目标是否一致。 |
| **研究侧线索** | 多通道反馈（视触听）在部分任务中可提升一致性与在场感 | 支持「在现有触觉上加**极克制**的听感提示」的渐进路线，而非一上来长叙事。 |

**归纳假设（待验证）**：入门用户更吃「人声 + 可预期节奏」；进阶用户更吃「少语言、少口令、音/触即可」。Grepu 可用**分层默认**降低一次性投入。

## 4. 如何用这个包做「Go / No-Go」判断

建议在试听 `demo_S4_two_cycles_tone_only.wav` 与 `demo_V_ALL_same_script_sequential.wav` 后，快速记三个问题的答案：

1. **无语言纯音路线**是否已经足够表达「下一阶段产品差异化」？若够，则优先做音色体系 + 设置项，人声可后置。
2. **多语言人声**带来的时长与混音成本，团队是否接受（预算、周期、包体或按需下载）？
3. 若做人声，更接受 **「仅开场 20–40 秒教学 + 主体仍靠音/触」** 的折中，还是坚持 **「全程口令」**？

若三项都倾向「后置人声 / 折中」，则下一阶段更适合：**产品规格 + 小规模用户访谈**，再进入工程实现。

## 5. 技术备注（生成方式，便于你或同事复现）

- 纯音 Demo：`generate_tonal_demos.py`（Python 标准库，无第三方依赖）。
- 人声 Demo：macOS `say -v <音色> -o 输出.aiff "文案"`，再用 `afconvert` 转 WAV。**注意**：`-o` 须在朗读文本之前，否则可能得到空音频。
- 在部分自动化/沙盒环境中，`say` 可能无法写入有效波形；本地终端直接运行一般正常。

## 6. 建议的下一步（在你评估之后）

- **若 No-Go 人声**：把规格收敛为「双音高边界 + 可选极短开场（仍可无语言）」，与现有 `MeditationPhaseCuePlayer` 哲学一致。
- **若 Go 人声**：单独立项「内容管线」：脚本字数上限、每语言母带规范、是否按需下载、与固定节拍的对齐策略（分轨 / 分语言时间线）。
